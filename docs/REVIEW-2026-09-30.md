# Review and UI migration, 2026-09-30

Baseline: `master` at `aa71af9` (after the September 20 parser/synchronization fixes).
Scope: frontend, responsive behavior, accessibility, preferences, calculation regressions and publication compatibility. No live Google Sheets refresh or production deployment was performed during this review.

## Findings and implemented fixes

| Priority | Finding | Result |
| --- | --- | --- |
| High | An unguarded `localStorage.getItem` ran during startup; restricted storage could stop the entire app. | Storage reads/writes now fail safely. The calculator works in memory when storage is unavailable. Tests cover blocked storage and malformed preferences. |
| High | Simply introducing Vite would break publication: the workflow copied source files, and runtime generated-data imports depended on their source URL. | CI builds `dist/`; publication copies the built site. Stable `src/data/*.generated.js` files remain available for local sync and for preserving the latest published data on the next deployment. A production-build browser test covers refresh after token authentication. |
| Medium | Subscription/optional income settings were kept only in memory. | Persist validated, known option values separately per game. Existing selected-game key is preserved. |
| Medium | `Hide UI` only changed opacity and pointer events, leaving hidden controls in the keyboard focus order. | Dashboard unmounts while hidden; the restore button remains available. |
| Medium | Desktop chart values depended on a pointer/canvas. | Expandable numeric source details are available on desktop as well as mobile. Keyboard and screen-reader accessible shadcn Accordion replaces hand-built mobile DOM. |
| Medium | Most backgrounds were 1.8–3.8 MB. | Serve 1920px WebP variants of approximately 132–192 KiB while retaining the original artwork files. |
| Medium | Custom controls and a 742-line DOM controller made UI changes harder to maintain. | React state and official shadcn/ui components replace the DOM controller. Calculation modules and Go parsers remain separate. |
| Low | The document declared Russian while most UI text was English. | Set document language to English; use consistent English number/date formatting. |
| Low | Chart animations did not respect reduced-motion preferences. | Honor the reduced-motion setting and stop pending chart animations when its component unmounts. |

## Implemented UI

- React 19, Vite 7 and Tailwind CSS 4 with locked npm dependencies.
- Official shadcn/ui Button, Card, Badge, Switch, Select, Accordion, Dialog, Input, Label and Sonner components, customized with Catppuccin Mocha tokens.
- Responsive game selector, stacked/two/three-column cards and touch-friendly settings.
- Mobile source breakdown at widths up to 760px. Desktop retains the existing custom stacked canvas chart and offers a numeric details view.
- Total pulls, average and currency pulls appear before the chart; resource totals follow it.
- Source spreadsheet link, update date and WIP warning remain visible.
- UID copy, game artwork, Hide UI and local-only owner synchronization are preserved.
- Repository link points to the development repository rather than the generated publication branch.

The custom canvas visualization remains custom code. It is not described as a shadcn Chart migration; interactive controls and the page interface have been migrated. The public site is still static and does not require a server, accounts or a database.

## Validation

- `npm test`: 15 checks pass, including all catalog option combinations, known calculation totals, atomic refresh, publish-baseline selection, sync failures and preference validation.
- `npm run build`: succeeds. Approximate gzip sizes: application 20.5 KB, vendor 123.7 KB, patch data 13.4 KB, CSS 7.6 KB. Separate chunks allow independent caching.
- Playwright: 28 checks pass in Chrome at 320, 390, 768 and 1440px. Covers all games, horizontal overflow, expandable sources, preference persistence, restricted storage, hidden UI, local-only sync, token cancellation/reopening and authenticated runtime module refresh.
- Mobile and desktop screenshots inspected visually.
- `npm audit`: zero known dependency vulnerabilities at review time.
- `go test -race ./...` and `go vet ./...`: both pass locally; CI runs them again before publication.

Browser verification used Chrome downloaded from Google because this environment's Playwright Chromium download endpoint returned invalid archives. CI uses the normal Playwright browser installation. These tests emulate mobile viewport/touch behavior in Chrome; they are not physical iOS/Safari or Android device tests.

## Recommended next improvements

| Order | Improvement | Why and boundaries |
| --- | --- | --- |
| 1 | Patch-range selection, with a recent-patches preset | HSR/Genshin history is long. Reduce mobile scrolling and make total/average values meaningful for a chosen period. Apply one range to chart, details and totals together. |
| 2 | Shareable scenario URLs | Encode game, range and income settings in a validated URL. Friends can compare the same assumptions; local preferences should not override explicit URL parameters. |
| 3 | F2P / monthly pass / battle pass comparison | Show additional pulls against the same free baseline. Endfield currently defaults to a paid tier; preserve that existing behavior here, but make the selected assumptions more explicit or offer a deliberate new default. Never imply that all displayed income is free. |
| 4 | Per-source freshness and incomplete-data warnings | The current update timestamp is a generation timestamp, not proof that every source is final or freshly verified. Expose parser warnings when data is WIP or deferred. |
| 5 | Export and import preferences | Helpful when changing browsers or clearing site data. This app currently has device-local settings, not a cloud save. |
| 6 | Component extraction and additional browser engines | Split App into dashboard controls, totals and chart components as features grow; add Safari/WebKit coverage when an appropriate runtime is available. |

Accounts, a database and a backend rewrite are not needed for these improvements. Personal pull-history tracking would be a separate product feature with different data requirements; the current site estimates income from patches.

## Publication notes

Review in a pull request before merging. A merge into `master` triggers the tested GitHub Pages publication workflow. Scheduled sync still preserves the published generated-data baseline and refuses publication on source failures. Original generated modules are copied after the Vite build, so the next deployment can read `origin/github-pages:src/data/<game>.generated.js` unchanged.

To run locally: `npm ci`, `npm run dev`. To use owner sync, also start `(cd tools/patchsync && go run . --serve)` or use `make serve`. To verify the built site: `npm run build`, `npm run preview`.

## Follow-up: long histories and patch ranges

- Default to the latest 10 available patches (including WIP), with latest 5, all-history and custom inclusive endpoints.
- Apply one selection to the chart, mobile and desktop source details, all resource totals and the average. Display the selected period and selected/available patch counts above the summary cards.
- Preserve each game's selection separately. Latest presets automatically include newly synchronized patches. Missing saved endpoints are clamped to the available history; crossing endpoints in the UI selects a single patch.
- Reserve at least 64 CSS pixels per patch slot in the desktop chart. Only the chart viewport scrolls horizontally; keyboard arrows can scroll it too. Switching ranges resets the scroll position.
- Move the source legend below the plot; highlighting remains available by pointer hover and keyboard focus. Hover information stays inside the visible scrolled viewport.
- Do not force a value label into an already occupied text lane. WIP badges and numeric source details remain available.
- Added four domain/preference checks (19 JavaScript checks total) and eight viewport-specific browser checks (36 browser checks total). Browser tests assert selected totals against catalog calculations, inclusive custom boundaries, persistence and scroll containment. CI saves range screenshots for visual review.

Patch-range selection, previously priority 1, is implemented in this follow-up. Shareable scenarios and F2P/paid comparisons remain the next product improvements.
